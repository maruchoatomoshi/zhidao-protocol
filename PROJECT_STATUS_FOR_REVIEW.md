# ZHIDAO Protocol — описание проекта и текущий статус (для внешнего ревью)

**Дата:** 2026-06-14
**Репозиторий:** `maruchoatomoshi/zhidao-protocol`
**До поездки:** 5 дней
**Цель документа:** дать другому AI-ассистенту (ChatGPT) с доступом к этому репозиторию полный контекст, чтобы он мог самостоятельно проверить код, найти неточности и оценить готовность.

---

## 1. Что это за проект

ZHIDAO Protocol — Telegram Mini App (фронтенд) + FastAPI-бэкенд + отдельный Telegram-бот, объединённые в игровую платформу для группы из ~85 человек (школьная поездка). Тематика: киберпанк/NetWatch + Genshin Impact кроссовер. Игровые механики поверх реальной жизни поездки: ведение дневника, утренние/вечерние проверки присутствия, командное сюжетное событие "Architect Protocol".

Это **проект одного разработчика**, активно развивается (164+ коммитов за последний месяц), без CI и автотестов.

## 2. Архитектура и файлы

### Frontend (Telegram Mini App, classic scripts, НЕ ES-модули)
- `index.html` (~2700 строк) — разметка всего приложения, все страницы как `<div id="page-...">`, переключаются через JS-навигацию. Скрипты подключены через `<script src="...">` в конце файла в определённом порядке — порядок важен, так как все файлы делят один глобальный JS scope (позже загруженный файл может молча перекрыть функцию с тем же именем из ранее загруженного).
- `css/styles.css` (~15 700 строк) — монолитный CSS, несколько тем: `theme-netwatch` (тёмная, по умолчанию), `theme-netwatch-light`, `theme-genshin`, `theme-admin-light` и т.д.
- `js/*.js` — около 20 файлов, каждый отвечает за свою область:
  - `config.js` — Telegram WebApp init, API URL, константы
  - `state.js` — общее состояние (текущий юзер, баланс, admin-флаг, тема)
  - `api.js` — обёртки запросов к бэкенду
  - `ui.js` — навигация, общие хелперы (включая корректный `escapeHtml`)
  - `themes.js` — переключение тем
  - `telegram-compat.js` — iOS/Telegram safe-area фиксы
  - `shop.js` — магазин, инвентарь, покупки
  - `casino.js` — кейсы, рулетка, Genshin "молитвы"
  - `leaderboard.js` — рейтинги
  - `diary.js` — дневник, оценки 💎 (раньше ⭐), архив для админов
  - `admin.js` — админ-панели
  - `raid.js` — рейды
  - `events.js`, `architect-event.js` — событие Architect Protocol
  - `blackwall.js`, `schedule.js`, `announcements.js`, `laundry.js`, `achievements.js`, `team.js`, `contracts.js` — отдельные фичи

### Backend
- `zhidao_api_ready.py` (~8100 строк, 121+ эндпоинт) — FastAPI, единственный источник истины для экономики (★ баллы, REP репутация). SQLite база (`/root/zhidao.db`), WAL-режим. **Это файл-источник в репо; на сервере крутится `/root/zhidao_api.py`, который может отличаться — перед деплоем нужно сверять диффом.**
- `zhidao_bot_ready.py` — отдельный процесс Telegram-бота (второй писатель в ту же SQLite БД). Обрабатывает команды `/award`, `/зп` (зарплата), и cron-задачи (APScheduler) для ежедневных пассивных бонусов от имплантов (Caishen, Qilin, NetWatch, Moon, Red Dragon).

### Документация в репо
- `CLAUDE.md` — главные правила работы с проектом, история инцидентов, чек-листы деплоя
- `ECONOMY_PASSPORT.md` — формальное описание экономики (★/REP, источники, лимиты)
- `PROJECT_ASSESSMENT.md` — независимая оценка от 2026-06-08 (надёжность БД, риски)
- `FEATURE_FREEZE.md`, `OPS_RECOVERY_RUNBOOK.md`, `SECURITY_HARDENING.md`, `CLAUDE_HANDOFF_REPORT.md` — операционные документы

- `USER_GUIDE.md` — инструкция для конечных пользователей

## 3. Экономика (ключевые правила)

- `★` (points) — трачиваемая валюта: магазин, кейсы, рейды, контракты, переводы.
- `REP` (rep_score) — публичная репутация, растёт **только** от оценок дневника, не тратится и не передаётся. Падает от штрафов за присутствие.
- Принцип: **бэкенд — источник истины**, фронт только визуализирует. Не менять вероятности/награды без обсуждения (см. `ECONOMY_PASSPORT.md`).
- Дневник: 💎 (1/2/3) → +15/+30/+50★ и REP, + опциональный бонус +20★/+20 REP.
- Присутствие: roll-call утром/вечером, штраф за пропуск (★ и REP), награда — попытка крутки кейса (кап 7/неделю).
- Защитные предметы магазина:
  - **Иммунитет (150★)** — полностью блокирует следующий штраф (любой источник).
  - **Терракотовая броня** — снижает штраф на 5★.
  - **Амнистия** — ручная отмена штрафа админом по скрину.
- Рейды: вход -50★, выигрыш +100★, шанс ~40%.
- Пассивный доход от имплантов (Caishen +15★/24ч, Qilin per-owner, NetWatch +25★ утром, Moon +12★/24ч, Red Dragon x1.2/x2 по воскресеньям) — реализован в `zhidao_bot_ready.py` через APScheduler cron-задачи в 08:01-08:04 по пекинскому времени.

## 6. Что хотелось бы от ревью ChatGPT

Свежий взгляд на:
- Любые расхождения между фронтендом (`index.html`, `js/*.js`) и бэкендом (`zhidao_api_ready.py`) — вызовы несуществующих эндпоинтов, устаревшие поля и т.п.
- Безопасность: проверка Telegram initData, переменная `TELEGRAM_AUTH_REQUIRED` (должна быть `1` на проде), защита admin-эндпоинтов.
- Экономические дырки: можно ли получить ★ или предметы дублированием запросов, race conditions при покупках/штрафах.
- Любые другие "штрафные пути" (по аналогии с иммунитетом), которые могут не проверять защитные предметы пользователя — стоит грепнуть по всем местам, где списываются ★/REP как штраф, и убедиться, что везде вызывается одна и та же цепочка хелперов (`try_block_penalty_with_immunity` → `try_block_penalty_with_terracota` → card-based reductions).
- Мёртвый код / неиспользуемые CSS-классы / недостижимые ветки.
- Любые console-errors при открытии приложения (если есть возможность прогнать через браузер).
