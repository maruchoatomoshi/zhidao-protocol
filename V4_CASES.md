# V4 — кейсы и личная коллекция

Реализация 2026-09-08, ветка `codex/v4-cases`. На опубликованный сервер
в этом проходе **не выкладывалась**. Согласованный первый этап — кейсы до
перекличек; попытки выдаёт организатор. MAX и существующие аккаунты сохранены.

## Что работает

- Баланс ★, запас 0–7 попыток, инвентарь и история изолированы по
  `(season_id, account_id)`. Старт — 0 ★ / 0 попыток; старые базы не импортируются.
- Открытие стоит одну попытку. Все розыгрыши, начисления и сохранение результата
  делает сервер в одной `BEGIN IMMEDIATE` транзакции.
- Организатор выдаёт 1–7 попыток выбранным участникам либо одной группе.
  Панель: **Кейсы → Выдача попыток**, видна только с правами этого сезона.
  Требуются причина и подтверждение. Журнал показывает запрос, реальную
  прибавку, остаток, инициатора и время. При запасе 6 и выдаче 4 начисляется 1.
- Денежные выигрыши, дополнительная попытка и Гарант судьбы действуют сразу.
  Гарант тратится только на пустышке и перебрасывает её внутри обычного кейса
  с исключением пустого результата; сам гарант также может выпасть снова.
- Предметы с `effect_state=pending` сохраняются, но не применяются. Это
  импланты и «+30 минут свободы». Купон пока **не разрешение на выход**:
  использование, погашение и сроки ещё не подключены. Нет скрытых таймеров
  сгорания до запуска этого сценария. Дубликаты хранятся количеством;
  экипировка, прочность, разбор и пассивные начисления не реализованы.
- Нет продажи попыток, Двойного сигнала, карточных молитв, штрафов, REP,
  перекличек, магазина или переноса между сезонами. Кейсы не меняют REP.
- «Два легендарных» означает два вида, не глобальное ограничение количества.
  NetWatch по-прежнему не входит в дроп.

## Единый источник и защита

`zhidao_v4/static/app/assets/cases/cases.json` задаёт веса, стоимость,
награды и состояние эффектов. Сервер читает его при старте, проверяет формат,
считает `rules_version` и отдаёт через `/api/v4/cases/rules`. Интерфейс
вероятностей читает этот API, а не отдельную таблицу. После изменения правил
нужен перезапуск API; существующие открытия хранят снимок своего выигрыша.

Миграция `0006_cases.sql` аддитивна: `v4_case_wallets`,
`v4_case_inventory`, append-only `v4_economy_operations`. Идемпотентность
использует существующий `v4_idempotency_keys`, административный аудит —
`v4_audit_log`. Миграции 0001–0005 не менялись.

POST требует сессию, CSRF cookie/header и `X-Idempotency-Key`. Ключ связан
с инициатором, операцией и хешем параметров, включая сезон. Повтор с другими
параметрами получает 409. Проверка доступа предшествует replay; завершение
сезона запрещает новые операции, но не повторное чтение своего сохранённого
результата с прежним ключом. Отзыв роли/участия закрывает доступ.

Глобальные operator/architect/system_admin работают во всех сезонах;
сезонные — только в назначенном. Играть даже организатор может лишь при
активном личном участии: неограниченных бесплатных административных кейсов нет.
Получатели выдачи — активные аккаунты/участники; групповая выдача берёт только
действующих member/leader этой группы. Группа другого сезона отклоняется.

API:

```text
GET  /api/v4/cases/rules                         публичные правила
GET  /api/v4/cases/context                       доступные сезоны и возможности
GET  /api/v4/seasons/{id}/cases/state             баланс, инвентарь, история
POST /api/v4/seasons/{id}/cases/open              открытие, тело не определяет участника/награду
GET  /api/v4/seasons/{id}/cases/history?before=N  страницы по 50
GET  /api/v4/seasons/{id}/cases/inventory
GET  /api/v4/seasons/{id}/cases/admin/roster
GET  /api/v4/seasons/{id}/cases/admin/grants?before=N
POST /api/v4/seasons/{id}/cases/admin/grants
```

Выдача: `{"account_ids":[12,13],"group_id":null,"amount":2,"reason":"Участие"}`.
Для группы вместо списка — `account_ids: []` и `group_id`. В ответе —
`results` с `requested`, `granted`, `scans` по каждому получателю.
Открытие возвращает `opening_id`, `prize`, `tier`, `guard_used`, `stars`,
`scans`, `season_id`, `rules_version`; replay ставит `X-Idempotent-Replayed: true`.
Все V4 API-ответы получают `Cache-Control: no-store`.

Браузер хранит только ключ и параметры незавершённого запроса, привязанные
к аккаунту/сезону. Ни токены, ни баланс, ни результаты не берутся из localStorage.
После потери связи/5xx сохраняется тот же ключ. После перезапуска доступно
«Восстановить результат»/«Восстановить выдачу»; совершённые открытия также
доступны из серверной истории. Предпросмотр оформления не запрашивает личные
API; истечение сессии очищает личный интерфейс и возвращает вход.

## Подготовка реального сезона — только после согласования

Аккаунт и участие в сезоне — разные сущности. Автоматически включать всех
аккаунтов, активировать draft или выдавать стартовые попытки код **не будет**.
Существующие `provision --list` и `roles` остаются способом работы с аккаунтами.
Для явного состава добавлен короткий локальный maintenance-инструмент:

```text
python -m zhidao_v4.season_roster --db <база> --season hainan-v4 \
  --actor-id <системный-администратор> --account-ids 12 13 \
  --group-code group-a --group-name "Группа А" --activate
```

Без `--apply` это dry-run. Проверить отчёт, затем повторить с `--apply`.
`--activate` нужен только при сознательном переводе draft → active; без него
статус сезона не меняется. Группа необязательна. Инструмент не сбрасывает
прогресс, не перемещает человека из другой группы и не восстанавливает
withdrawn/completed-участие. Запускать вручную, не из бота/фонового цикла.
Перед любой реальной миграцией сделать согласованную резервную копию SQLite.
Production/test-server deploy не является частью этой локальной реализации.

## Оформление и локальный просмотр

Новые `case-workstation.css` и `case-play.js` не вводят фреймворков.
Стекло, тропический фон и существующие иконки сохранены. Добавлены оконная
панель, сегментное ожидание, строки состояния, окно выигрыша и папка коллекции.
Текст читаемый, кнопки основных действий ≥44 px, анимация не определяет
результат и отключается через `prefers-reduced-motion`.

```powershell
.\.venv-web\Scripts\python.exe -m tools.preview_v4_cases --port 8784
```

Открыть `http://127.0.0.1:8784/app/`. **Только тестовые** логины:
`case.student` / `case.operator`, пароль у обоих `preview-only-passphrase`.
Этот helper не принимает путь к существующей базе, создаёт временную БД,
слушает только loopback и не обращается к MAX. Завершение процесса удаляет
временную БД. Данные тестовые, не прогресс настоящих участников.

- `.venv-web` pytest: **98 passed, 1 deselected, 1678 subtests passed**.
  Исключён только legacy-import, для которого в этом окружении нет `pytz`.
- `.venv-travel` unittest `test_v4*.py`: **82 tests OK**, включая совместимость
  с настоящей старой схемой; отдельно `test_v4_migrations.py`: **4 tests OK**.
  Эти прогоны пересекаются; складывать числа в общий счётчик нельзя.
- 14 новых case-тестов: все призы/веса, расход гаранта, лимит, группа,
  отсутствие прав, отзыв, изоляция, rollback, restart, конкурентные открытия
  и выдачи, пагинация, безопасная настройка состава.
- Playwright/Edge: предпросмотр без личных API, настоящее открытие и баланс,
  потеря ответа после commit + reload + replay без повторной награды,
  коллекция, выдача с подтверждением. **0 JS exceptions**.
- Дневные/ночные скриншоты; отсутствие горизонтального переполнения страницы
  кейсов при ширинах 320, 360, 390, 768 и 1280 px.
- Артефакты: `.codex-tmp/cases-qa/`; воспроизведение —
  `node tools/check_v4_cases_ui.cjs` с доступным Playwright и установленным Edge
  (другой channel задаётся `CASES_BROWSER_CHANNEL`).
- Проверка content-hash ресурсов и `git diff --check` пройдена.

**Не проверено:** настоящий мобильный MAX, устройство участника, серверный
деплой и производственные данные. Existing MAX-auth tests прошли, но они не
заменяют проверку контейнера. Перед публикацией пройти запуск из бота,
сопряжение, сворачивание/возврат, Back и повтор открытия при плохой связи.
Ранее замеченную недоступность музыки на опубликованном сервере этот этап
не исправляет и не выдаёт за проверенную.
