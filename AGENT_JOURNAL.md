# AGENT_JOURNAL — общий журнал находок

Короткие записи от всех агентов. Читается за минуту, экономит часы.

Это **не** отчёт о проделанной работе и не замена handoff-документам. Сюда
пишется только то, что следующему агенту нужно знать, чтобы не потратить
время впустую: установленные факты, тупики, найденные причины поломок.

## Формат

```
## ГГГГ-ММ-ДД · агент · направление

**Факт / Тупик / Причина:** одна строка сути.
Чем подтверждено — число, файл, коммит. Если это догадка, пишем «предположение».
```

Новые записи — **сверху**. Старые не редактируем и не удаляем: если запись
устарела, добавляем новую с пометкой, что она отменяет предыдущую.

**Главное правило: записывай измеренное, а не предполагаемое.** Догадка,
записанная как факт, через два агента станет основанием для плана.

## 2026-09-05 · Claude · карта, пропавший квартал общежитий

**Причина:** в квартале с круглой площадью не было ни одного здания, хотя
жилая зона там размечена. Оказалось, наш экстракт из OSM брал **только `way`
и молча пропускал `relation`**. Четыре общежития там — мультиполигоны
(`relation/15068735…15068738`, по 28 вершин), плюс `relation/15068734`
(`building=university`). Импортированы как есть, обводить ничего не пришлось.
Стало 88 объектов и 18 общежитий вместо 14 — ровно столько, сколько
`building=dormitory` отдаёт Overpass.

**Правило:** при выборке из OSM всегда спрашивать `way` **и** `relation`.
Отсутствие объекта в выборке — не доказательство отсутствия в источнике.

**Тупик, проверенный четырежды:** автоматическая обводка зданий по снимку
Esri не работает. Пробы цвета: кровля 43,40,35 и 71,74,57 и 132,129,112,
дорога 85,86,80, промежуток между корпусами 101,101,93 — тона перекрываются,
поэтому наращивание от затравки утекает с крыши на асфальт, а порог по
яркости (150/178/185 при насыщенности 30–40) ловит парапеты и дорожки вместо
кровель. Снято три маски, все показаны и отвергнуты по изображению.

**Тупик:** притягивание рёбер к градиенту яркости (`snapEdge`/`snapQuad` в
`scratchpad/align/trace.js`) само по себе исправно находит кромки, но не
спасает, если исходный прямоугольник поставлен неверно: пробный контур попал
на теневой промежуток между корпусами, и алгоритм послушно сел на не ту
кромку — ошибка порядка ширины здания. Глазомер по тайлам 256×256 остаётся
слабым звеном, и обводить так нельзя.

**Инструмент:** `scratchpad/align/` — мозаика тайлов Esri z18 (максимум для
этого района, z19 отдаёт «Map data not yet available») с нашими контурами
поверх, в общей системе координат. Тайлы отдаются с CORS, пиксели читаются,
`fetch`+`createImageBitmap` вместо `Image.decode()` — последний не разрешается,
пока панель браузера скрыта. Этим инструментом и был найден пропавший квартал.

**Факт:** пешеходных дорожек в OSM по-прежнему нет: Overpass по
`footway|path|pedestrian|steps|cycleway|track|service|living_street` в рамке
кампуса даёт ноль. Зданий в рамке — 32.

## 2026-09-04 · Claude · карта, подписи

**Причина:** размер подписи задавался в единицах карты, а слой масштабируется
трансформацией, поэтому при зуме буквы росли вместе с картой и закрывали то,
что подписывают. Теперь базовый размер лежит на узле в `data-base-size`, а
`applyView` делит его на текущий масштаб — на экране подпись одного размера при
любом зуме. Пересчёт только при смене масштаба: `getBBox` дёргает пересчёт
вёрстки, на каждый `pointermove` это дорого.

**Замер:** масштаб 1 — кегль 29.99, масштаб 3.11 — кегль 9.65. Отношение
совпадает с масштабом, то есть экранный размер постоянный.

**Сделано:** вторая строка по-китайски в `tspan` с `font-size: .68em` и
`dy` в em — обе величины относительные, поэтому строка переживает зум сама.
Подписи общежитий появляются с масштаба 2.2 и не схлопываются в одну: у
`dorm` отключено слияние по имени, иначе четырнадцать зданий давали одну
подпись. Номера общежитиям не присваиваются — их нет ни в OSM, ни в снимке,
а выдумать номер значит соврать про то, где человек живёт.

**Сделано:** разбор наложений жадный, по приоритету, пересчитывается на каждом
шаге зума. На общем плане остаются 11 подписей из 29, при зуме 3.11 — 22,
включая 7 общежитий. Приоритет: библиотечный комплекс, учебные корпуса,
столовые, актовый зал, спорт, жилые зоны, дороги, общежития. Спорт опущен ниже
учебных корпусов сознательно: в корпус идут каждый день, на корты нет.

**Тупик:** внутренних дорожек кампуса в OSM нет вовсе. Overpass по
`footway|path|pedestrian|steps|cycleway|track|service|living_street` в рамке
кампуса вернул ноль линий. Значит дешёвого источника нет, остаются только
обводка по разрешённому снимку и съёмка GPS на месте.

**Факт:** снимок с retromap.ru — это тайлы `mt{n}.google.com/vt/lyrs=s`,
то есть Google в обход его API. Привязка **совпадает с нашим WGS-84**: контур
стадиона из OSM ложится на стадион на снимке, сдвига GCJ-02 нет (он был бы
100–600 м). Но обводить с Google нельзя: наши данные под ODbL, и срисованная
геометрия загрязняет набор необратимо. Легальная замена той же детальности —
Esri World Imagery (`server.arcgisonline.com/.../World_Imagery/MapServer/tile/
{z}/{y}/{x}`), у неё есть разрешение на обводку для OSM.

**Подтверждено снимком Esri:** библиотечный комплекс из пяти безымянных
контуров `amenity=library` — это те самые треугольные корпуса с парусной
кровлей, тайл z17 105591/58717. Отметка теннисных кортов попадает на реальные
корты, тайл z18 211182/117436. `verified` у обоих остаётся `false`: снимок
подтверждает опознание, но не заменяет замер ногами.

## 2026-09-04 · Claude · карта, туман по контуру

**Причина:** подготовленная область была прямоугольником по габаритам кампуса,
а кампус — вытянутый многоугольник. В углы прямоугольника попадали чужие дороги,
в том числе деревня на северо-востоке, и она выглядела как разрешённое место.
Область теперь считается как объединение колец: контур кампуса плюс следы всех
недорожных объектов, отступ задаётся толстой обводкой чёрных фигур в SVG-маске
(`stroke-width = 2 * padding`, 110 единиц). Дороги в объединение не входят:
иначе подготовленным станет всё, куда ведёт асфальт.

**Замер:** снаружи OSM-контура лежат ровно два объекта — актовый зал на 61 м и
безымянная жилая зона на 110 м. Отступа в 55 м им не хватало, поэтому в маску
включены сами постройки, а не только контур. В браузере: 42 фигуры в маске,
все 14 общежитий доступны для выбора, 30 объектов интерактивны, 30 дорожных
сегментов снаружи помечены `is-unexplored`.

**Проверка укрывистости:** туман временно залит `#ff0000` — карточка стала
сплошной красной везде, кроме силуэта кампуса. Значит непрозрачность 1
действительно перекрывает всё, и прежние «просвечивающие дороги» были не
утечкой, а дорогами внутри светлой области. Смотреть на глаз здесь бесполезно,
цвет-индикатор решает вопрос за один кадр.

**Замена:** проверки «на территории» переведены с `insideBounds` (прямоугольник)
на `regionContains` (точка в кольце или ближе `padding` к нему). Это касается
выбора объектов, подписей, дорожного графа и маршрутизации. Габаритный
прямоугольник остался только для кадрирования и раскладки подписей.

## 2026-09-04 · Codex · карта, режим исследования

**Факт:** карта теперь различает подготовленный сектор и неизведанное
окружение. Сектор вычисляется по восьми исходным контурам обязательных POI и
исходной OSM-точке спортцентра; нарисованные прямоугольники тенниса и
спортцентра границу не определяют. Это состояние интерфейса, а не
административный или измеренный контур (`campus.geojson`, блок `exploration`).
Измеренный сектор с отступом — примерно 1033 × 631 м, полный показанный кадр с
полосой неизведанного окружения — примерно 1283 × 881 м.

**Проверка:** в живом браузере загружены 84 объекта; 14 доступны для выбора,
57 объектов вне сектора исключены из мыши и клавиатурного фокуса. Отдельно
проверены выбор мышью и Enter, единственная подпись библиотечного комплекса,
маска, граница сектора и отсутствие ошибок/предупреждений в консоли.

**Причина бага:** `setPointerCapture()` переносил итоговый `click` с SVG-path
на корневой SVG, поэтому объект не выбирался мышью. Тап теперь активирует
исходную цель `pointerdown`, а последующий нативный click кратко подавляется;
drag не превращается в выбор точки.

**Факт:** участнический `/app/` получает `Permissions-Policy` с
`geolocation=(self)`, а `/architect/` и API сохраняют `geolocation=()`.
Локальный сервер на `127.0.0.1:8770` перезапущен и оба заголовка проверены
реальными HTTP-запросами.

## 2026-09-04 · Claude · карта, второй заход

**Факт:** первая выборка из OSM была слишком узкой — брала только `way` с
именами. Расширенный запрос дал то, что важнее всего: **14 общежитий**
(`building=dormitory`), **5 корпусов библиотеки** (`amenity=library`, без имён)
и жилые зоны `学生生活一区` / `学生生活二区`. Первая совпадает с AMap-идентификатором
`B0LRFH6LH5` из handoff-а. Итого 84 объекта вместо 22.

**Ловушка классификации:** кампус `黎安国际教育创新试验区` и три института помечены
одинаково — `amenity=university` без тега здания. Различать только по имени,
иначе граница территории теряется и ломается кадрирование.

**Приём:** координату теннисных кортов, которых нет в OSM, взяли со снимка
Baidu **относительным** измерением от стадиона-якоря из OSM. Сдвиг BD-09 на
дистанции в 240 м почти одинаков для обеих точек и при вычитании сокращается,
поэтому результат остаётся в WGS-84. Помечено `approximate: true`, точность
порядка ±30 м, нужен GPS-замер на месте.

**Правило:** снимок провайдера годится, чтобы **опознать** объект, но не чтобы
обвести с него геометрию — это и другой датум, и производная работа от
лицензированного снимка.

**Причина бага:** размер подписей задавался в пользовательских единицах SVG, а
они здесь метры. 11 единиц при виде на 1250 м давали три пикселя на экране.
Размер считается от ширины кадра.

## 2026-09-04 · Claude · карта кампуса

**Факт:** геометрия кампуса есть в OpenStreetMap и берётся без всякого ключа.
Nominatim находит территорию по запросу `陵水黎安国际教育创新试验区`
(18.4016895, 110.0164028), Overpass отдаёт 22 именованных объекта с контурами:
границу территории, стадион `体育场`, `公共教学楼`, `1号食堂`, корпуса трёх
институтов, дорожную сеть. Граница 1172 x 1391 м, 1.63 кв.км.

**Факт:** предупреждение handoff-а подтвердилось замером — `公共教学楼` и
`公共实验楼` разные здания, между центроидами 222 м.

**Не найдено в OSM:** библиотека `图书馆` (обязательный POI) и `立德路`
(западная граница). Записаны в блоке `missing` файла campus.geojson,
догадками не заполнены.

**Решение (пользователь, отменяет §7 handoff-а):** живой подложки от AMap не
будет. Ключ требует китайской верификации личности, единственный путь — просить
китайского коллегу подставить свои документы, и пользователь отказался это
делать. Вместо неё своя векторная карта.

**Почему WGS-84, а не GCJ-02:** GPS телефона отдаёт WGS-84, поэтому отметка
«где я» ложится без единого преобразования. Старое предупреждение про смешение
систем координат теперь действует в обратную сторону: **нельзя рисовать эти
координаты на тайлах AMap или Baidu** без конверсии.

**Причина бага:** первое кадрирование считалось по всем объектам, и школа в
1.3 км растягивала экстент так, что кампус съёживался в угол. Кадрируем по
полигону границы.

**Причина бага:** `.map-point-card` в app.css это grid `42px 1fr` под старую
разметку с номерным кружком; у новой карточки один дочерний блок, он попадал
в колонку 42 px и заголовок переносился по буквам.

## 2026-09-04 · Claude · модель Архитектора, волосы

**Тупик:** воксельное сплавление прядей в единую причёску не работает. Пряди
толщиной 2–3 мм: воксель 0.0035 даёт 64 300 треугольников, прореживание до
2200 (коэффициент 0.034) рвёт поверхность; воксель 0.009 оплавляет пряди в
комки и пробивает дыры. Проверены оба конца диапазона (версии v23, v23b).

**Тупик:** единая оболочка вращения — от кромки внизу до одной макушки —
всегда даёт каре. Топология не способна выразить пряди, идущие вверх и в
стороны. Ужимание массы с 103 до 86 мм и продольные жёлобы не помогли
(v25, v26).

**Факт:** лепестки должны идти вдоль черепа и отрываться только в последней
трети длины. Радиальный пуск от корня даёт «паучьи лапы» и голую макушку
(v27 против v28).

**Вывод о методе:** процедурная подгонка органической формы сходится плохо —
восемь версий без попадания. Для таких задач агент готовит сцену, лепит
пользователь. Файл `game_assets/architect/architect-hair-MANUAL.blend`.

## 2026-09-04 · Claude · модель Архитектора, лицо

**Факт:** в `architect-v16-unity-manifest.json` стоит `"rig": false` и
`"shape_keys": false`. В одиннадцати модулях **нет геометрии глаз, рта и
зубов** — лицо целиком нарисовано в атласе, область `head`, v 0.58–0.98.
Следствие: мимику деформацией сделать не на чем, только текстурный путь.

**Причина:** материал `v16_Skin_and_optional_cyber_cheek` адресует картинку
самодельной сетью с узлом `ABSOLUTE` по локальной X — **лицо складывается
зеркально** по центральной линии. Корректирующий узел Mapping через такой
сгиб не композируется: попытка развалила лицо, один глаз исчез.
Рабочее решение — не трогать сеть, а пересобрать изображение в раскладке,
которую сеть ожидает.

**Факт:** старый источник лица был референсом в полный рост 1086×1448, лицо
занимало участок ~90×160 пикселей. Мыльность была следствием отсутствия
данных, а не качества рисунка.

**Факт:** на `Head_Architect` есть три shape key диапазоном −1…+1:
`Jaw_width`, `Head_width`, `Nose_projection`. Применены −0.70 и +0.85
(челюсть и нос) после развёртки вариантов.

## 2026-09-04 · Claude · V4-приложение, дизайн

**Причина:** фотографию фона гасил не `body`, а `.app-shell` — белый градиент
непрозрачностью 88/77/94%. Искали не там.

**Причина:** вкладки показывались одновременно, потому что `.board-list
{ display: flex }` побеждает браузерное `[hidden] { display: none }` —
специфичность равная, а авторский CSS идёт после UA. Лечится глобальным
`[hidden] { display: none !important; }`.

**Факт:** Google Fonts заблокирован в материковом Китае, а приложение для
поездки туда. Шрифт самохостится в `assets/fonts/`. Тот же урок уже был
оплачен в сезоне 1 — медиа уводили с GitHub Pages на гонконгский сервер.

**Факт:** Georgia использовалась в девяти селекторах вместо одного,
предусмотренного `V4_DESIGN.md`, включая числа и шевроны.

## 2026-09-04 · Claude · CI

**Причина:** проверка пробелов `git diff --check HEAD~1 HEAD` **никогда не
работала**. `actions/checkout` клонирует глубиной 1, `HEAD~1` не резолвится,
шаг падал — и это глушилось хвостом `|| true`. Когда `|| true` убрали на
ветке v4, шаг начал ронять каждый пуш. Починено: `fetch-depth: 2` плюс
`.gitattributes` с `*.md -whitespace` (коммиты `06b994b`, `49610d3`).

**Незакрыто:** шаг проверки JavaScript не покрывает
`zhidao_v4/static/app/app.js` — основной файл участницкого приложения.

## 2026-09-04 · Claude · метод

**Правило:** сравнивать рендеры только при одинаковых камере, свете и
масштабе, одним скриптом. Сравнение текстурированного рендера с процедурным
едва не привело к ложному выводу о потере текстуры.

**Правило:** когда критерий вкусовой, а параметр числовой — не гадать, а
делать развёртку вариантов и показывать пользователю. Так за один заход
решилась форма головы.
